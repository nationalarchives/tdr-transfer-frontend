About TDR Connector for SharePoint

The TDR Connector for SharePoint provides a mechanism for copying files and their metadata at source from SharePoint into the TDR web application, to allow transfer of content to The National Archives.

The TDR Connector for SharePoint:

  • uses SharePoint REST APIs to extract the content and metadata;
  • integrates with the TDR application;
  • copies selected SharePoint content to AWS S3 bucket hosted by TDR;
  • copies SharePoint metadata as a JSON object from the selected SharePoint content to AWS S3 bucket hosted by TDR.

Installation

The SharePoint SPFx application can be installed at:

  • Tenant level; and/or
  • Site collection level

Records Transfer Page Provisioning

Before the Records Transfer functionality can be used, a dedicated SharePoint site page must be provisioned to host the Records Transfer SPFx web part.

This is a one-time administrative configuration that must be completed after the application is installed on the target SharePoint tenant/site.

The page can be provisioned using one of the following methods:

  • Automated (Recommended): Execute the provided Deploy-S3TransferWebPart.ps1 deployment script. The script performs the following actions:
    • Installs the application on the target site.
    • Creates the RecordsTransfer.aspx page under the Site Pages library.
    • Adds the Records Transfer web part to the page.
    • Publishes the page.
  • Manual: If the deployment script is not used, perform the following steps manually:
    • Navigate to Site Contents → Site Pages.
    • Create a new page named RecordsTransfer.aspx.
    • Add the Records Transfer SPFx web part to the page using the web part toolbox.
    • Publish the page.

Important: The page name must be RecordsTransfer.aspx, as the List View Command Set is hardcoded to redirect users to this page. If the page does not exist or the Records Transfer web part has not been added, the transfer functionality will not be available, and users will be unable to initiate the records transfer process.

Authorisation

Whether a user is permitted to use the TDR Connector for SharePoint to copy records from SharePoint to TDR is based on two criteria, the user has a:

  • SharePoint account that allows read access to the records to be copied; and
  • valid TDR account.

Both conditions must be true for the user to be able to copy the records from SharePoint to TDR.

Before Transferring Content from SharePoint to TDR

Excluding SharePoint Site Name on the Public Catalogue (Discovery)

By default the TDR Connector uses the SharePoint site name as part of the file path when copying metadata. There maybe circumstances where it is not appropriate for the site name to be used.

If the site name should not be used then inform your transfer adviser that the SiteName should be ignored BEFORE proceeding with a transfer for the first time.

For instructions on how to do this, see section: Ignoring the SiteName

Note: this process is temporary, until a new feature is added to the TDR Connector for SharePoint to allow the user to select whether to ignore the SiteName or not, without the need to contact a transfer adviser.

How to use TDR Connector for SharePoint

Step 1: Ensure “third party cookies” are enabled on the web browser

What Happens

The TDR Connector for SharePoint makes use of a signed cookie to ensure that only the TDR user can copy the records into the TDR AWS infrastructure.

Step 2: Navigate to folder(s)/file(s) to transfer in SharePoint

What Happens

Standard SharePoint view of content.

Step 3: Select the folder(s)/file(s) to transfer to TNA via TDR

What Happens

Standard SharePoint item selection functionality.

Step 4: From the “actions” menu bar select “Upload to TDR”

What Happens

Opens up the TDR Connector for SharePoint.

Step 5: Click “Sign in to Transfer Digital Records” button

What Happens

Redirects to the TDR login page to establish a secure connection between SharePoint and TDR to allow the copy of data.

If the user already has a valid TDR session open the user does not need to re-enter the credentials for their TDR account and Step 6 is skipped.

Step 6: Enter TDR user credentials in the TDR login page

What Happens

Taken to TDR login page to enter user credentials, once valid credentials are entered the user is taken back to the TDR Connector for SharePoint.

The TDR Connector for SharePoint retains the access token retrieved from entering the correct credentials.

Step 7: Click “Continue” button

What Happens

User is taken to the next step in the process.

TThe TDR Connector for SharePoint retrieves configuration to support the copying process. This includes:

  • Capacity limits;
  • SharePoint system metadata to retrieve;
  • Display configuration;

Step 8: Click “Start Upload” button

What Happens

In TDR a consignment is created, including a unique reference for that consignment, and the copy of selected files and their metadata is initiated.

For selected content, two uploads are made:

  • File; and
  • Metadata JSON object for file

The metadata JSON object contains the SharePoint metadata retrieved from the selected content, and additional generated content to support the processing of the content within TDR.

For details on what metadata is retrieved and how this maps to TDR metadata fields see this section: SharePoint Metadata Handling

Step 9: Wait for select folder(s)/file(s) to be copied to TDR

What Happens

Selected files and their attendant metadata copied from SharePoint and sent to TDR holding area.

On completion processing of the copied content is initiated in TDR.

Step 10: Receipt of email confirmation of upload process to TDR

What Happens

Once the processing of the copied content has been completed, an email will be sent to the TDR user’s email address, with instructions for continuing the transfer within the TDR web application.

On receipt of email confirmation follow the instructions.

If the upload process was:

  • successful the user is invited to continue the transfer journey within TDR.
  • unsuccessful for whatever reason the email will contain instructions on what to do next.

What Happens Next

For a successful copy of items from SharePoint to TDR the email will provide a link to the next step in the transfer process within the TDR web application.

If the copy of the items from SharePoint to TDR is unsuccessful the email will provide instructions as what to do next.

Depending on whether you have an active TDR web application session, or not, the email link with take you directly into TDR web application without the need to log in.

SharePoint Metadata Handling

SharePoint System Metadata

A sub-set of the SharePoint “system” metadata for the selected content is retrieved by the SharePoint to TDR Connector.

The exact metadata can change, but will include the following to provide the minimum metadata required by The National Archives:

  • FileLeafRef (maps to TDR metadata field file_name);
  • Modified (maps to TDR metadata field date_last_modified);
  • Length (maps to TDR metadata field file_size);
  • FileRef (partially maps to TDR metadata field file_path);
  • SiteName (partially maps to TDR metadata field file_path) (this is the value of display name of the site);
  • LibraryName (partially maps to TDR metadata field file_path) (this is the value of the display name of the library)

SHA256 Checksum

In addition to the SharePoint system metadata the SharePoint to TDR Connector generates a SHA256 checksum of the file (excluding the metadata) to use for file integrity checks within the TDR application once the copy is completed.

TDR Connector for SharePoint Added Metadata

The TDR Connector for SharePoint adds additional metadata required to support the transfer to TDR.

This includes:

  • matchId (generated UUID to reconcile metadata JSON to copied file object)
  • transferId (TDR consignment UUID from provided by TDR API endpoint)
  • source (to identify the system where the transfer came from, ie “SharePoint”, hard coded value)#
  • userId (TDR user account UUID from the access token)

Mapping SharePoint Metadata to TDR file_path Metadata Property

To meet TNA archival requirements TDR maps three SharePoint metadata field values into the file_path property:

  • FileRef;
  • SiteName;
  • LibraryName.

In the above example the following SharePoint metadata will be extracted:

SharePoint Metadata Property SharePoint Metadata Value
SiteName TkTest
LibraryName TK Test Library
FileRef /sites/Retail/tkTestLibrary/testFolder/rnd_1000.jpg

The TDR file_path metadata value is in the format of:

/{SiteName value}/{LibraryName value}/{folder / sub-folders path}/{file name}.{extension}

From the example this gives a file_path value of:

/TkTest/TK Test Library/testFolder/rnd_1000.jpg

Note: “sites” is a static value used across all SharePoint tenants and is ignored by TDR

By default the LibraryName value will be included as part of the “arrangement” on Discovery. For the example above this will lead to an “arrangement” on Discovery of:

{series} >> TkTest >> TK Test Library >> testFolder

Ignoring the SiteName

The SiteName can be ignored at the transferring body level.

To do this: Inform your transfer adviser that the SiteName should be ignored BEFORE proceeding with a transfer for the first time.

Once your request has been received, then:

  1. the transfer adviser will request the override to be applied to TDR;
  2. TDR will be configured to ignore the SiteName
  3. the transfer adviser will inform you the override has been put in place
  4. you can then proceed with your transfer.

With the override in place, for the example above, the “arrangement” on Discovery will be:

{series} >> TK Test Library >> testFolder

Note: this process is temporary, until a new feature is added to the TDR Connector for SharePoint to allow the user to select whether to ignore the SiteName or not, without the need to contact a transfer adviser.
